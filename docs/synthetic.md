# Synthetic — Cut & Paste 합성 결함 + 입력 정렬 (ResNet-18)

[baseline.md](baseline.md)의 지도학습 ResNet-18 에 **합성 결함 데이터를 더하면 좋아지는가**, 그리고 **나사를 세워 해상도를 올리는 입력 정렬이 얼마나 효과가 있는가**를 본 실험 기록.
코드는 `src/supervised/{synth,align,bigtest}.py`, 실행은 `experiments/supervised/synthetic_*.ipynb`(커널 `screw_defect`). 결정 근거는 [decisions.md §14](decisions.md).

- 주지표는 baseline 과 같은 **F2**(불량 미검출 FN 최소화), 위치는 Grad-CAM/LayerCAM 의 **Pixel AUROC · AUPRO**
- 평가는 항상 **합성 0장의 real test**. k-fold 는 쓰지 않고 `학습 → 평가` 한 번(시드 5개 반복)
- baseline 분할의 test 는 결함 19장뿐이라 **작은 차이는 구분되지 않는다**(§6). 그래서 test 를 키운 분할을 따로 만들었다(§7)

## 1. 합성 방법 (`src/supervised/synth.py`)

결함 GT 마스크로 결함 패치를 오려, 정상 나사의 **같은 위치**에 붙인다.

```mermaid
flowchart LR
    A["결함 이미지 + GT 마스크"] --> B["패치 추출<br/>마스크 확장(5px)+패딩, 최대 연결요소만"]
    B --> C["나사 PCA 주축 좌표 (t, s)<br/>t: 머리→끝 0~1, s: 폭 방향 -1~1"]
    C --> D["정상 나사의 같은 (t, s) 로 이동<br/>회전(축 각도 차이 ±10°)·배율 0.85~1.15"]
    D --> E["유효성 검사<br/>중심이 몸체 안, 마스크 90% 가 몸체 31px 이내"]
    E --> F["cv2.seamlessClone (NORMAL)<br/>+ 합성 GT 마스크 저장"]
```

- 전경: Otsu 후 배경 중앙값 − 90 보다 어두운 픽셀(그림자를 몸체로 오인하지 않기 위함)
- 유형별 균등 배분. 합성 총량 = 정상 수 × 비율(0.25 → 65장 = 유형당 13, 0.5 → 130, 1.0 → 260)
- 앞에서부터 N장을 쓰므로 비율이 달라도 풀이 서로 포함(nested) 관계
- 정의는 별도 매니페스트 `splits/synthetic_split.csv`(원본/소스/대상/위치/각도/시드), 이미지는 `outputs/synthetic/`(gitignore)

**누수 통제**: 합성의 소스 결함과 대상 정상은 **train 의 80%(학습분)에서만** 뽑는다. val·test 는 real only. test 결함은 합성 소스로 쓰지 않는다.

## 2. 실험 설정

| 항목 | 값 |
|---|---|
| 모델 / 학습 | ResNet-18, Adam 1e-4, `CrossEntropyLoss(weight=[1, 2.0])`, 40 epoch, best val F2 저장, patience 10, batch 16 |
| 분할 | baseline train 425 → 80/20 stratified(seed 42) = 학습 340 / val 85, test 55(결함 19). 시드 0~4 는 재학습만 변경 |
| 비교 | 합성 비율 `0 / 0.25 / 0.5 / 1.0` × 시드 5, 시드로 짝지은 paired t-test |
| 입력 ① base | Resize 256 → 224 (baseline 과 동일, RandomRotation 180 등) |
| 입력 ② align | 나사를 PCA 주축으로 세워(머리 위) 원본 px 320×960 캔버스에 담고 0.4 배(128×384) 입력. 증강은 ±8° 회전·이동·배율·좌우 반전·밝기 |
| 위치 평가 | test 결함 19장, 224 프레임에서 Pixel AUROC·AUPRO. align 의 CAM 은 원본 프레임으로 역투영 후 같은 crop |

입력 정렬(`src/supervised/align.py`)의 동기: 1024px 를 224 로 줄이면 약 40px 결함이 10px 안팎이 된다. 나사는 이미지의 일부라서 세워 자르면 같은 계산량에서 해상도를 2배 이상 올리고 회전 변동을 없앨 수 있다.

## 3. 결과 ① — 기존 입력(base): 합성은 Recall·위치에 도움, 정밀도는 손해

| 합성 비율 | Test F2 | Image AUROC | AUPRO (GradCAM/L4) |
|---|---|---|---|
| 0.0 | 0.778 | 0.969 | 0.556 |
| **0.25** | **0.881** | 0.959 | 0.808 |
| 0.5 | 0.842 | 0.934 | 0.806 |
| 1.0 | 0.821 | 0.899 | 0.815 |

- 0.25 에서 F2 +0.102 이지만 **통계적으로 유의하지 않다**(p=0.12). 위치(AUPRO 0.556 → 0.8 안팎)와 Recall 개선이 일관됐다.
- 비율이 올라가면 정상 오경보(Precision)와 Image AUROC 가 나빠진다 → 합성은 많을수록 좋지 않다.
- 이 분할의 base 0.0 F2(0.778)는 문서화된 baseline(0.885~0.904)보다 낮다. 원인은 확인하지 못했다(분할·학습 재현 차이 미검증).

**CAM 방법·층**: 재학습 없이 저장된 20개 모델에 5개 방법(GradCAM·GradCAM++·HiResCAM·LayerCAM·XGradCAM) × 2개 층(layer3 14×14, layer4 7×7)을 적용했다(`synthetic_cam_methods.ipynb`).
- layer4(7×7)는 작은 결함에 너무 거칠어서 **layer3 로 바꾸는 것만으로** 합성 0.0 의 Pixel AUROC 0.807 → 0.928, AUPRO 0.556 → 0.797 이 됐다.
- 즉 "합성이 위치를 올린다"는 해석은 방법·층에 따라 달라진다. layer4 에서 GradCAM = HiResCAM = XGradCAM (avgpool+fc 구조라 동일).

## 4. 결과 ② — 입력 정렬: 가장 큰 개선 요인

정렬 입력(`align_0.4`)을 합성 비율별로 학습(시드 5, `synthetic_align_ratio_experiment.ipynb`).

| 합성 비율 | Test F2 | Recall | FP | FN | Image AUROC | AUPRO (GradCAM/L4) |
|---|---|---|---|---|---|---|
| **0.0** | 0.946 ± 0.060 | 0.937 | 0.2 | 1.2 | 0.998 | 0.944 |
| 0.25 | 0.914 ± 0.044 | 0.895 | 0.0 | 2.0 | 0.992 | 0.947 |
| 0.5 | 0.964 ± 0.045 | 0.958 | 0.2 | 0.8 | 1.000 | 0.966 |
| 1.0 | 0.915 ± 0.080 | 0.905 | 0.6 | 1.8 | 0.995 | 0.950 |

같은 비율·같은 시드에서 base → align:

| 합성 비율 | F2 | AUPRO (GradCAM/L4) | Image AUROC |
|---|---|---|---|
| 0.0 | 0.778 → 0.946 | 0.556 → 0.944 | 0.969 → 0.998 |
| 0.25 | 0.881 → 0.914 | 0.808 → 0.947 | 0.959 → 0.992 |
| 0.5 | 0.842 → 0.964 | 0.806 → 0.966 | 0.934 → 1.000 |
| 1.0 | 0.821 → 0.915 | 0.815 → 0.950 | 0.899 → 0.995 |

- Image AUROC·Pixel AUROC·AUPRO 는 **모든 비율에서 5/5 시드가 정렬 쪽이 우세**. F2 는 0.5(+0.121, p=0.02)·1.0(+0.094, p=0.04)에서 유의.
- 정렬 크기는 0.4 배가 0.6 배(192×576)보다 나쁘지 않았다(0.6 이 더 낫지 않음).
- **정렬 입력에서 합성의 추가 이득은 구분되지 않는다**: 합성 0.0 대비 F2·Recall 차이는 모두 p=0.50~0.62. 평균은 0.5 가 가장 높지만(F2 0.964) 단조롭지 않고 0.25 는 오히려 낮다.
- 합성 0.5 에서만 LayerCAM/layer3 위치 지표가 유의하게 좋았다(Pixel AUROC 0.995 p=0.02, AUPRO 0.986 p=0.01, 5/5 시드). 절대값이 이미 0.99 안팎이라 실질 차이는 작다.
- 합성을 넣으면 선택 epoch 가 빨라진다(약 6~10 vs 합성 없음 16).

> 정정: 중간 보고에서 "정렬 + 합성 0.25 가 최선"이라고 했으나 위 표로 **철회**한다. 정렬 입력의 최선은 F2 기준 0.0 또는 0.5 이고, 0.25 가 최선이라는 근거는 없다.

## 5. 해석

- **입력 정렬이 주 요인**이다(위치·Image AUROC·정상 오경보). 합성은 base 입력에서만 분명히 유효했다.
- baseline 분할(결함 19장)에서는 정렬 입력의 합성 이득이 **구분되지 않았다**(§4). test 를 키운 재평가(§7)에서는 정렬 입력에서도 위치 지표와 F2(N=50)가 합성으로 개선되는 경향이 나왔다. 따라서 "합성 무용"이 아니라 **평가 표본이 작아 가려지지 않았던 것**으로 보는 쪽이 맞다.
- 해상도 효과와 정렬 효과는 분리하지 못했다. 비정렬 고해상도(예: Resize 448) 대조군이 필요하다.

## 6. 한계

- **test 결함 19장·시드 5개**: 결함 1장이 F2 를 약 0.05 움직인다. 지표가 0.95~1.0 으로 천장에 붙어 +0.02 차이는 못 가린다. p 값은 다중비교 보정을 하지 않았다.
- **val 포화**: 정렬 입력에서 val F2 가 ≈1.0 이라 "val F2 최고 epoch" 선택이 의미 없다(선택 epoch 가 합성 유무에 따라 크게 달라지는 이유일 수 있음).
- 합성 풀은 한 번 생성(시드 7)한 것만 썼다. 합성 품질(블렌딩 모드, 위치 지터)에 대한 민감도는 보지 않았다.
- baseline·이상탐지 지표와는 split 이 달라 직접 비교하지 않는다([decisions.md](decisions.md) 와 동일 방침).

## 7. test 를 키운 재평가 (`bigtest`)

baseline test(결함 19장)로는 §4 의 작은 차이를 가릴 수 없어서 480장을 합쳐 **test 결함을 30/40/50장으로 늘린 분할**에서 같은 실험(base/align × 비율 4 × 시드 5)을 다시 한다.

- 분할(`src/supervised/bigtest.py`, 매니페스트 `splits/synth_test{N}_split.csv`): 결함은 유형당 N/5 장, 정상은 baseline 비율(결함 19 : 정상 36) 유지. 30 ⊂ 40 ⊂ 50 포함 관계. `baseline_split.csv` 는 그대로 둔다.

| N | test 결함 / 정상 | train(학습+val) 결함 / 정상 |
|---|---|---|
| 30 | 30 / 57 | 89 / 304 |
| 40 | 40 / 76 | 79 / 285 |
| 50 | 50 / 95 | 69 / 266 |

- 합성 풀은 분할마다 그 train 안에서 새로 만든다(누수 통제 동일). 학습·평가 설정은 §2 와 같다.
- 실행: `NTEST=40 jupyter nbconvert --execute synthetic_bigtest_experiment.ipynb`, 결과 `outputs/synth_exp/t{N}/runs.csv`.
- 이 분할의 수치는 baseline 분할 결과와 직접 비교하지 않는다.

| 50 | base | 0.757 | 0.764 (.84) | 0.766 (.84) | 0.809 (.40) |
| 50 | align | 0.901 | 0.955 (.07) | 0.956 (.06) | 0.959 (.01) |

**AUPRO (GradCAM/layer4)**

| N | 입력 | 0.0 | 0.25 | 0.5 | 1.0 |
|---|---|---|---|---|---|
| 30 | base | 0.422 | 0.600 (.16) | 0.623 (.05) | 0.713 (.06) |
| 30 | align | 0.888 | 0.918 (.26) | 0.937 (.09) | 0.935 (.25) |
| 40 | base | 0.277 | 0.543 (.00) | 0.670 (.00) | 0.656 (.02) |
| 40 | align | 0.858 | 0.904 (.12) | 0.935 (.02) | 0.911 (.17) |
| 50 | base | 0.310 | 0.616 (.00) | 0.665 (.00) | 0.670 (.01) |
| 50 | align | 0.819 | 0.902 (.01) | 0.926 (.01) | 0.920 (.01) |

- **정렬 효과는 세 크기 모두에서 재현**됐다. 같은 비율에서 Image AUROC 0.85~0.90 → 0.99 이상, 정상 오경보(FP) 약 13~26장 → 0~4장, 위치 지표도 크게 올랐다. base 입력은 정상 오경보가 많아(test 정상 57~95장 중 5~26장) 정밀도가 낮다.
- **합성 효과는 test 를 키우자 정렬 입력에서도 보이기 시작**했다. 위치 지표(AUPRO·Pixel AUROC)는 N=40·50 에서 합성 0.25~1.0 이 0.0 보다 일관되게 높았고(N=50 은 p≈0.01~0.03), F2 도 N=50 에서 0.901 → 0.955~0.959(1.0 은 p=0.01), N=40 에서 0.886 → 0.961~0.965(p 0.07~0.12). N=30 은 정렬 0.0 의 F2 가 0.954 로 이미 높아 차이가 없다.
- 합성 비율의 최적점은 크기마다 달랐다(F2 는 0.5~1.0 에서 비슷, 0.25 는 약함). 비율 1.0 도 정렬 입력에서는 해롭지 않았다. 앞의 baseline 분할 결과(§4)에서 0.25 가 낮았던 것은 잡음이었을 가능성이 높다.
- 합성 효과는 **합성 없음(0.0)의 성능이 낮을수록 크다**(N=40·50 의 align 0.0 은 F2 0.89~0.90, N=30 은 0.95). 학습 결함이 줄어든(N 이 클수록) 조건에서 합성이 더 필요해진다는 해석과 맞지만, 이 실험만으로 인과를 단정하지는 않는다.

주의
- N=30 ⊂ 40 ⊂ 50 이고 시드가 같아 **세 결과는 독립적인 반복이 아니다.** "세 번 재현"이 아니라 한 분할 계열에서의 경향이다.
- p 값은 다중비교 보정을 하지 않았다. test 결함이 늘면서 학습 결함이 함께 줄어, 평가 정밀도 향상과 데이터 부족 효과가 섞여 있다.
- 합성 0.0 의 결과가 N 에 대해 단조롭지 않다(align F2 0.954 → 0.886 → 0.901). 분할 하나의 운에 좌우되는 부분이 크다는 뜻이다.
